01

Quick start

Radiators combines a parametric CSXCAD geometry editor with the openEMS finite-difference time-domain (FDTD) solver. CSXCAD describes geometry, materials, feeds and the computational grid; openEMS solves the electromagnetic fields. You can design, inspect, simulate and compare antennas without installing desktop CAD software.

  1. Open the CSXCAD editor. Choose More → Open example… → Half-wave dipole 2.45 GHz (fast). Start with this known small example before building your own model.
  2. Inspect the two dipole arms, feed, materials and domain in Model. Turn on Ports and Mesh in the viewport; check the feed gap.
  3. Open Checks. Resolve errors and evaluate warnings. Open Simulation, choose Browser, and start with a small CPU allocation, such as two threads.
  4. Choose Run in browser. Watch the progress and solver log. When complete, open Results and inspect S11, input impedance and radiation.
  5. Save the antenna JSON and Download result.json. Change one dimension, rerun, and compare; do not assume a pretty radiation plot proves a good match.

First run: Browser mode needs a compatible browser and cross-origin isolation. The app may reload once to activate its service worker. Use Chrome on HTTPS or localhost if an embedded browser cannot run the solver. Remote mode is useful on mobile or for larger jobs.

02

Workspace and viewport

Model / Inspector

The Model tree lists geometry, materials, ports and diagnostic objects. Select an item in the tree or viewport to inspect its fields. Use the add controls to create new items. A scripted instance selects as one object, even if it generates multiple pieces.

Params / Scripts / JSON

Define reusable numeric parameters, create scripted geometry, preview sweep cases, or edit the complete schema-v2 source.

Checks / Simulation / Results

Validate the current design and all sweep cases, configure the mesh and solver, monitor jobs, and review computed or imported results.

Desktop uses a model tree, 3D viewport, inspector and resizable lower dock. Drag the dock grip to resize; double-click to reset. On phones the viewport is full screen and panels open as bottom sheets; drag the handle up for more space, down to close. Android Back closes a sheet.

ControlPurpose
Persp / Iso / Top / Front / RightPerspective, orthographic isometric and axis-aligned views. Geometry uses a right-handed XYZ coordinate system, Z up.
Domain / Ports / Grid / X-rayShow the domain and refinement boxes, feed objects, construction grid at global Z=0, or transparent solids.
MeshInspect computed rectilinear grid in XY, XZ, YZ or 3D. Slice, opacity, Min cell and PML controls reveal local spacing.
Object selection / XYZ gizmoPick a primitive or point, then manipulate its position or editable coordinate handles. Check the inspector afterward.
TouchOne finger orbits, two fingers zoom/pan, tap selects.
Undo / RedoUndo or redo model edits; Ctrl+Z / Ctrl+Shift+Z on desktop. Ctrl+S saves antenna JSON.

The eye icon changes preview visibility only. The geometry enable checkbox (or Simulation control in Inspector) changes the actual model: "enabled": false excludes the object from simulation, script expansion, validation and meshing while preserving its source. A hidden reflector still affects the antenna if it is enabled.

03

Geometry, transforms and materials

Add a named material, then assign it to each geometry object. Dimensions are in millimetres in the saved configuration. Object priority controls which property wins when geometries overlap; inspect overlaps deliberately rather than using priority to conceal a broken feed.

PrimitiveRequired geometry fields / meaning
box / sheetstart, stop (XYZ corners). One zero-thickness axis gives a sheet.
cylinderstart, stop (axis endpoints), radius.
cylindrical_shellstart, stop, centerline radius, thickness.
sphere / spherical_shellcenter, radius; shell additionally takes thickness.
wirepoints (XYZ polyline), wire_diameter. Continuous finite-radius CSXCAD wire, not disconnected rods.
polyhedronvertices and faces (zero-based vertex indices); edit in JSON or generate by script. Use closed, consistently wound surfaces for solids.
Built-in scriptshelix (continuous wire), hemisphere (dome/shell), tapered_cylinder (cone/frustum, optionally hollow). Legacy helix and hemispherical shapes can be opened and converted.

Transforms

Rotation is applied around the local origin in X → Y → Z order, followed by translation. Angles are degrees. Design around a meaningful origin before rotating; translation is not a change of rotation pivot. For example:

JSON · Transform
"transform": {
  "rotate_deg": [0, 90, 0],
  "translate": [0, 25, 0]
}
Material typeFields and use
pecPerfect electric conductor. Ideal reference for metal geometry; no ohmic loss.
dielectricepsilon (relative permittivity), optional kappa_s_per_m (conductivity). Use measured substrate properties at the working frequency.
conductiveconductivity_s_per_m. Bulk lossy conductor; GHz skin depth may be far smaller than the grid.
conducting_sheetconductivity_s_per_m, thickness_m (metres, not mm). Use a zero-thickness box; e.g. 35 µm = 0.000035 m.

PEC is useful for early antenna comparisons. A copper conductivity value alone does not guarantee accurate conductor loss; validate skin-depth treatment, thickness and mesh convergence. A visual joint is not necessarily an electrical joint after discretization.

04

Ports and electrical connectivity

Every simulation must have exactly one excited port. Additional passive ports can represent loads where supported, but a run does not produce a full multiport S matrix. Each port needs a unique ID and must lie inside the computational domain.

TypeConfiguration
lumpedstart, stop, direction (x/y/z), impedance_ohm (typically 50), excite. Model a gap between the two terminals, with the axis aligned to the applied electric field.
coaxialstart/stop, propagation_direction, PEC metal_material, optional dielectric_material, inner_radius, outer_inner_radius, outer_radius. Radii must be strictly increasing.
mslstart/stop, PEC metal_material, propagation_direction and excitation_direction. Model the strip, dielectric and reference ground correctly.

Browser/WASM currently supports lumped ports. Use the native simulation path for coaxial or MSL configurations; the remote API receives resolved configurations, not generator or script source.

For a 2 mm feed gap along Z, a centered port may run from [0,0,-1] to [0,0,1]. Both arms should meet their respective end faces. Confirm the actual mesh samples both terminals; avoid relying on tangent point contacts of curved conductors. An intentional capacitive coupling design is different from a missing galvanic contact and needs independent validation.

05

Parameters, expressions and sweeps

Numeric fields accept literals, parameter names and numeric expressions. A parameter is a scalar. Define it once, reuse it in geometry, ports, mesh or other numeric fields, then adjust it with Params. Parameter renames update references. The resolved case substitutes numbers without destroying the editable source.

JSON · Parameters and geometry
"parameters": {"L": 58, "gap": 2, "spacing": 0.2},
"geometry": [
  {"name": "director", "material": "pec", "shape": "cylinder",
   "start": [0, {"$expr": "spacing*L"}, {"$expr": "-0.94*L/2"}],
   "stop": [0, {"$expr": "spacing*L"}, {"$expr": "0.94*L/2"}],
   "radius": 2}
]

This fragment uses driven-element length L as a reference. {"$param":"L"} references a single parameter; {"$expr":"0.94*L"} computes a numeric expression. Grammar: numeric literals, named parameters, + − * / % **, parentheses, min/max/abs/sqrt/sin/cos/tan/floor/ceil, pi/e. Trigonometric functions use radians. No arbitrary JavaScript or Python in expressions.

Workspace units

More → Workspace units sets display/input units per document. Example inputs: 2.45 GHz, 2450 MHz, {f_ghz*1000} MHz. A trailing unit applies to the entire expression; mixed-unit arithmetic within expressions is unsupported. Saved values use schema units: mm, Hz, degrees, Ω, S/m, GiB and metres for sheet thickness. Parameters and sweep axes remain scalars.

Sweep workflow

JSON · Sweep
"sweep": {
  "mode": "product",
  "parameters": {
    "L": {"values": [56, 58, 60]},
    "spacing": {"range": {"start": 0.15, "stop": 0.25, "step": 0.05}}
  }
}

Product produces all combinations: this example yields 3 × 3 = 9 cases. Zip pairs equal-length axes by index. Ranges include the stop only if a step reaches it. The schema permits up to 128 cases, but a coarse 9–16-case sweep is a sensible first pass. Use the case selector to inspect resolved geometry, then Run case, per-row Start, or Run all. Refine the best area with a narrower second sweep. Use Array… to repeat an object at an expression-defined step when topology is fixed.

Rank cases against a consistent frequency band and objective: match, realized gain, efficiency, front-to-back ratio, size or another engineering constraint. Do not select on peak directivity alone.

06

Scripted geometry

Use Scripts for repeated or variable-topology geometry such as Yagi directors, radial wires, arrays, meanders or coils. A script declares typed arguments and a generate function that returns CSXCAD primitives. Create an instance through the Model add controls; its inspector is generated from the declaration.

JavaScript · Geometry script
const args = {
  center: {type: "point", default: [0, 0, 0]},
  count: {type: "int", default: 3, min: 1, max: 20},
  length: {type: "length", default: 55},
  spacing: {type: "length", default: 20},
  radius: {type: "length", default: 2},
  material: {type: "material"}
};
function generate(a) {
  const [x,y,z] = a.center;
  return Array.from({length:a.count}, (_,i) => ({
    name: "element-" + i,
    shape: "cylinder",
    material: a.material,
    start: [x, y+i*a.spacing, z-a.length/2],
    stop: [x, y+i*a.spacing, z+a.length/2],
    radius: a.radius
  }));
}

Argument types: point, vector, length, number, int, angle, material, choice, bool. Optional declaration keys include default, label, hint, more, step, min, max, options (choice) and handle (length/number gizmo). A point can be manipulated by the XYZ gizmo. A handle can specify {from:"center", dir:[0,1,0], scale:1}. Use Copy as new script to customize a built-in; built-in names are reserved.

Scripts are stored under scripts.<name>.source. Instances use name, script and args; generated primitives receive instance-prefixed names. The editor uses a worker with a two-second script limit; the native pipeline uses the shared JavaScript expansion code and Node.js. Remote jobs receive already-expanded primitives. Use only trusted code. The Python generator option is for native repository runs: generated geometry is not available for editing/simulating directly in the browser.

07

Simulation domain and mesh

FDTD divides the domain into a rectilinear grid. Field updates occur in every cell, so a finer mesh can increase both cell count and the number of timesteps. Domain bounds, local feed features and material wavelengths all matter.

Domain and boundaries

Set Start and Stop XYZ to enclose all geometry, sources and the required free-space margin. Boundary order is X−, X+, Y−, Y+, Z−, Z+. PML_8 (eight absorbing layers) is a reasonable open-space default; PML_6/PML_4 use fewer layers. MUR is an alternative absorbing boundary. PEC and PMC are ideal electric/magnetic walls; use symmetry only when excitation and geometry justify it. Keep structures and the NF2FF surface away from absorbing cells. At 2.45 GHz free-space λ is about 122 mm; roughly λ/4 clear space is a useful initial margin, not a universal requirement or substitute for checking PML clearance.

Mesh settingEffect
Max cell / max_cell_mmMaximum target global cell width; begin around λmin/10 to λmin/20 in the highest-permittivity region, then verify convergence. Features can be smaller.
Growth ratio / growth_ratioLimits grading between neighbouring cells; valid range 1.01–2. Smaller ratios grade more gently, potentially adding cells.
Max cells / max_cellsSafety budget for total cells, not a target. Nx × Ny × Nz gives the cell count.
Local min cell / local_min_cell_mmOptional automatic fine target near small features. auto_refine_max_span_mm limits which features qualify.
Grid mode / grid_modeFeature: geometry/port planes plus graded refinements. Uniform: equal spacing per axis chosen from uniform_step_mm (or global max); ignores local refinement boxes.

Refinement boxes

Simulation → Refinements → + Box or + Around feed. Around feed uses the current case, 5 mm padding and 0.25 mm resolution as a starting point. Set Start/Stop, Resolution and optionally Edit in 3D. The purple box can be manipulated using its corners. An enabled refinement needs Stop > Start on every axis.

JSON · Mesh settings
"mesh": {
  "max_cell_mm": 5, "growth_ratio": 1.4,
  "max_cells": 5000000,
  "refinements": [
    {"start": [-5,-5,-4], "stop": [5,5,4], "resolution_mm": 0.5},
    {"start": [-2,-2,-2], "stop": [2,2,2], "resolution_mm": 0.25}
  ]
}

In feature mode, regions with a spacing equal to or larger than the global target are ignored. Where regions overlap an axis interval, the finest requested spacing wins; protected geometry/port planes are retained and transitions are smoothed. Refinements are not layered duplicate grids. Close protected planes can still force extremely small intervals. The fine X, Y and Z lines extend across their full axes because openEMS uses a rectilinear grid.

Inspect the actual grid

Enable Mesh in the viewport, pick a plane, move Slice to the feed, and use Min cell to locate the smallest interval. Inspect grid spacing, contacts and PML. Browser mode offers Validate mesh / export PEC to perform operator setup without full FDTD and download discretized PEC edges as VTP. Inspect the actual metal representation rather than only the smooth CAD preview.

Smallest cell controls timestep: the Courant stability condition depends on the smallest spacings. A single sliver may force many updates for the same physical time. If a timestep warning appears, inspect the minimum cell, near-coincident planes and overly aggressive refinements. Do not simply increase max timesteps or remove all local feed resolution.

08

Excitation, solver and outputs

The Gaussian excitation supplies a frequency band around center_hz. bandwidth_hz is the half-width (fc), so the nominal band is center ± bandwidth. Put requested S11 frequencies inside this band and ensure useful incident energy at radiation frequencies. An S11 frequency grid is post-processing of a broadband time-domain run, not a separate FDTD run for every sample.

SettingMeaning
max_timestepsHard limit on updates. Larger values allow more simulated time but may cost more CPU.
end_criteriaEnergy-decay stopping threshold; 0.000001 (−60 dB relative energy) is the bundled dipole criterion. Smaller is stricter; resonant models may need longer.
outputs.s11One or more inclusive start/step/end sweeps in Hz.
radiation_frequencies_hzFrequencies at which NF2FF (near-to-far-field transformation) is requested.
radiation_gridtheta_step_deg and phi_step_deg. Smaller angle steps increase far-field sampling and output size; not FDTD mesh resolution.
include_impedance / include_realized_gain / include_polarizationOptional output quantities, when supported by the chosen solver path.
JSON · Solver and outputs
"excitation": {"center_hz": 2450000000, "bandwidth_hz": 350000000},
"solver": {"max_timesteps": 100000, "end_criteria": 0.000001},
"outputs": {
  "s11": [{"start": 2300000000, "step": 10000000, "end": 2600000000}],
  "radiation_frequencies_hz": [2450000000],
  "radiation_grid": {"theta_step_deg": 5, "phi_step_deg": 5},
  "include_impedance": true, "include_realized_gain": true
}

Reaching the timestep cap is not proof of convergence. If the run ends before excitation completes, tighten the energy criterion (for example, from 1e-4 to 1e-6) and rerun; increasing the cap alone does not prevent premature convergence. Inspect residual energy, waveforms and incident spectrum; repeat with finer mesh, adequate domain and a stricter/longer run until the quantities of interest stabilize.

09

Browser, remote and native runners

RunnerWhen to use
BrowserLocal WASM openEMS, lumped-port cases. No model upload. CPU engine (experimental) is default; Basic remains selectable. Requires isolation and SharedArrayBuffer.
RemoteNative openEMS on your Linux/WSL2 Docker host. Sends resolved input, polls logs/results and displays them in the same editor. Useful for mobile and large sweeps.
Native CLI / CIRepository scripts, trusted Python generators, native ports and batch execution. CI CPU/memory metadata is separate from the remote CPU-only budget.

Remote installation

Shell · Start remote runner
git clone https://github.com/winject-wireless/radiators.git
cd radiators
./run-remote.sh
# In another terminal:
./run-remote.sh --print-token

Requires Linux or WSL2, Bash, Python 3.10+ and Docker. The launcher builds/reuses the native solver image and creates private configuration at ~/.config/radiators-runner/config.json (or XDG_CONFIG_HOME). In Simulation select Remote, enter http://localhost:8765 for the same host or your trusted HTTPS hostname for another device, paste the access token and Test connection.

For Android or another machine use a trusted HTTPS endpoint, e.g. a reverse proxy forwarding to 127.0.0.1:8765. Set allowed origins to the exact editor origin (the hosted app is https://winject-wireless.github.io). Plain HTTP LAN access is not supported. Keep the token private; it authorizes all jobs and stays in editor memory until reload. See remote runner deployment guide for TLS, configuration and systemd startup.

CPU allocation

ncpu_pool is the total CPU budget; ncpu_per_job is each job's CPU request. Maximum concurrent cases is floor(pool / per job), limited by available cases and runner capacity. For example, 16 / 2 = 8 concurrent cases. Remote max_cpus is the aggregate server cap; Docker enforces per-job CPU quotas, not a RAM or swap quota. Host RAM can still run out. Native CI resource requests under solver.resources are not browser or remote RAM limits.

Run case executes the selected case; Start on a case row starts it if resources allow; Run all queues the snapshot of resolved sweep cases. Completed cases appear independently in Results. A failed case does not block the rest. Stop cancels remaining work and retains completed results; an early-stopped browser run can produce partial output. Inspect status and logs before treating any result as valid.

Remote jobs require status polling. The default job lease is 300 seconds; backgrounding or closing the editor can suspend polling, leading to cancellation. The server's temporary result retention is not durable across restart or eviction. Download finished results; update the runner checkout if newer diagnostic results are missing.

Native CLI example

Shell · Native simulation
docker build -t radiators-openems:ci -f docker/openems/Dockerfile .
docker run --rm -v "$PWD:/work" radiators-openems:ci \
  python antennas/simulate.py examples/dipole_2450.json \
  --output results/dipole_2450

To list expanded cases without solving: python3 scripts/sweep.py examples/helix_sweep.json. See the native schema and simulation guide for CI and generators.

10

Interpret simulation results

Results lists the selected case's available frequency-response charts, far-field patterns and diagnostics. For a sweep, the fixed case selector and mobile left/right swipe change results without changing the source geometry definition. Select a frequency in the viewport for the radiation surface.

MetricInterpretation
S11 (dB)20 log10 |Γ|. More negative means less reflected power at the reference impedance; −10 dB is a common matching threshold (10% reflected power).
VSWR(1+|Γ|)/(1−|Γ|). 1:1 is ideal; −10 dB corresponds to about 1.92:1. Very large values indicate near-total reflection.
Zin = R + jXInput impedance in ohms. R is resistance; X is reactance. X≈0 is resonance, not necessarily a good match. For a 50 Ω port, aim for R≈50 Ω and X≈0.
Directivity (dBi)Angular concentration of radiated power relative to an isotropic radiator; excludes conductor/dielectric loss and mismatch.
Radiation efficiency ηradRadiated power / accepted power. Ideal PEC often approaches unity; nonphysical values warrant checking convergence and normalization.
Mismatch efficiency ηm1−|Γ|² for the active port, under the usual real reference impedance.
Gain / realized gain (dBi)Gain = directivity × ηrad; realized gain = gain × ηm (linear factors). In dB add 10 log10 of each efficiency.
Normalized E-fieldRelative field magnitude by direction, not absolute received strength at a physical distance.

Example: 10 dBi directivity, 80% radiation efficiency and −10 dB S11 give approximately 8.57 dBi realized gain. Compare designs at the same frequency and reference impedance.

Radiation view

Toggle XY/YZ/XZ intersections independently. Follow point moves the enabled planes through the yellow sampling point; hiding it resets the planes to the origin. Select Sampling point or click its marker to use the translation gizmo. Reset returns to the peak direction. Point details reports angles, directional directivity/gain/realized gain and normalized E magnitude. The plot is angular far field: displayed millimetre radius is illustrative, not propagation distance or a near-field map. Theta is measured from +Z; phi is the azimuth in the XY plane.

For a free-space dipole, expect a broadside maximum and nulls along its axis. For a Yagi, compare forward and backward gain and the principal cuts, not just the lobe appearance. A good pattern with very low R can still have poor realized gain into a 50 Ω system.

11

Diagnostic probes and field playback

Add passive diagnostics in Model → Diagnostics to investigate current distribution, feed behaviour or local fields. These are different from ports and far-field sampling.

ProbePurpose
CurrentPlanar cross-section with chosen positive normal; use same reference direction and comparable area when comparing parasitic currents. Flatten to plane repairs a thick box.
VoltageAxis-aligned line with direction as reference.
E/H pointThree vector components at a single XYZ location.
Field dumpPlane/volume for E, H, J, J_total, D or B. J_total includes displacement current (curl H), not surface current.
JSON · Diagnostic probes
"probes": [
  {"name":"I_driven","type":"current",
   "start":[-5,-5,3],"stop":[5,5,3],"direction":"z"},
  {"name":"H_plane","type":"field_dump","field":"H",
   "start":[0,-30,-30],"stop":[0,30,30],
   "sub_sampling":[1,3,3],
   "time_domain":{"enabled":true},
   "frequency_domain":{"enabled":true,"frequencies_hz":[2450000000]}}
]

Use Results → Diagnostic probes and fields. Play/pause, seek, speed, spatial stride and arrow scale affect visualization only. Recorded time uses actual captured frames; frequency-domain phase animates complex phasors and is not recorded time. Negative scalar values reverse arrows; same-unit arrows use a shared scale. Mesh-snapped probe coordinates may differ from the requested geometry.

Capture small planes with subsampling before volumes. The diagnostic transport limits dumps to 4096 points each and four million aggregate sample values; native raw files can be much larger. Time capture defaults on; frequency capture is opt-in. Updated native remote runners support diagnostic probe result transport; browser-only mesh validation/PEC export and some solver diagnostic plots are not guaranteed remotely. See diagnostic schema and examples.

JSON, local projects and result archives

ActionWhat it does
Save JSONDownload the editable schema-v2 source with parameters, sweep and scripts. This does not include the computed result.
More → JSON source…Source is editable; Format prettifies valid JSON, Apply commits changes, Discard edits abandons pending changes. Resolved is read-only for the current case. Ctrl+Enter applies source edits.
More → Export resolved case JSONExport the numerical case, useful for native reproduction or debugging.
Save locally / Open local projects…Store and reopen named project snapshots on this device. Draft autosave also restores the current workspace.
OpenAccepts antenna JSON, result JSON or sweep ZIP. Use the import choice to retain existing results or explicitly replace matching entries.
Download result.jsonSave the selected available result, including embedded input and radiation records when provided.

Successful results are cached in IndexedDB by exact resolved input. Changing an electrical input creates a different case identity; editing does not make an old result valid for the new case. Reopening the same exact resolved case can restore the cached result. A failed, aborted or incomplete rerun should not replace a valid retained result. Workspace display units do not change the electrical cache key.

Local storage is per browser/profile/origin, not cloud sync or a permanent backup. Private browsing, clearing site data, storage quotas or browser eviction may remove local files. Keep JSON and ZIP backups. Avoid leaving unapplied JSON edits when navigating away; a local draft is not a substitute for a saved file.

Schema-v2 reference and example

JSON is strict: double-quoted keys and strings, no comments or trailing commas. The source is the editable antenna definition; the resolved config is numerical input for one case. Use schema_version: 2.

Top-level keyRole
schema_version / name / description / unitsVersion 2, project identity, notes and mm coordinate units.
parameters / sweepNamed scalars and case expansion.
domain / meshStart/stop, six boundaries, grid and refinements.
materials / geometryElectrical property definitions, named primitives or script instances.
ports / probesActive excitation, passive ports and optional diagnostics.
excitation / solverGaussian frequency band, stopping criteria and native resources.
outputsS11 sampling, far-field frequencies, angular grid and optional quantities.
scripts / generatorJavaScript geometry definitions; native-only trusted Python generator.
workspace_unitsDisplay preferences, not physical solver inputs.

Troubleshooting and engineering checklist

SymptomInvestigate / fix
Run button disabledCheck model errors, pending script expansion, runner availability and CPU slots. For Browser, open the app directly on HTTPS or localhost, allow isolation, try Retry isolation. For Remote, Test connection.

Before trusting an antenna result

  1. Check physical dimensions, units, material properties, connectivity and source orientation.
  2. Inspect actual mesh around feeds, thin conductors, substrate and PML; run operator validation if available.
  3. Ensure the excitation covers the requested frequencies, and inspect incident power and convergence.
  4. Repeat with refined mesh, larger domain or longer solve as needed; compare resonance, impedance and realized gain quantitatively.
  5. Save the source and result together. Measure the built antenna with a calibrated VNA and appropriate radiation setup; simulations do not replace physical verification or regulatory certification.

Installation and further reading

The editor is a static web app and can be installed as a PWA on compatible browsers. Use Chrome on Android and Install app if offered. Offline availability follows the cached app assets; remote execution requires a connection to the runner. The Capacitor APK is a separate packaging route; WebViews may lack SharedArrayBuffer.

Shell · Local setup
cd site/csxcad
python3 prepare.py
python3 -m http.server 8080 --directory www
# Open http://localhost:8080/
node check.mjs

For developers, the editor implementation guide covers the build, Android packaging and parity tests. openEMS documentation describes the underlying FDTD solver and CSXCAD. Report reproducible issues at Radiators issues with build hash, source JSON, selected case, runner, relevant log and result (remove private tokens and confidential geometry before sharing).
